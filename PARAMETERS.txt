校园微气候监测后端参数说明
========================================

一、服务概览
----------------------------------------
服务名称：Campus Weather Monitor API
技术栈：Go 1.27、chi、Huma、pgx、goose、PostgreSQL
默认监听端口：8000
API 文档：/docs
OpenAPI 描述：/openapi.json
健康检查：GET /health
前端仪表盘：apps/web（默认开发端口 5173，容器端口 8080）

设备通过 HTTP 直接上报，固件仓库与 C/ESP-IDF 实现保持不变。

二、数据表
----------------------------------------
表名：measurements
迁移工具：goose（版本表 goose_db_version）
迁移文件：apps/api/internal/platform/migrate/sql/

id
  类型：SERIAL，主键，自增。

station_id
  类型：VARCHAR(64)，非空，建立单列索引。

observed_at
  类型：TIMESTAMPTZ，非空，建立单列索引。
  说明：传感器采集时间，统一存为 UTC。

received_at
  类型：TIMESTAMPTZ，非空。
  说明：服务器接收时间，统一存为 UTC。

temperature
  类型：DOUBLE PRECISION，非空，单位 °C。

humidity
  类型：DOUBLE PRECISION，非空，单位 %。

wind_speed
  类型：DOUBLE PRECISION 或 NULL，单位 m/s。

wind_direction
  类型：DOUBLE PRECISION 或 NULL，单位度。

co2
  类型：DOUBLE PRECISION 或 NULL，单位 ppm。

pm25
  类型：DOUBLE PRECISION 或 NULL，单位 μg/m³。

pm10
  类型：DOUBLE PRECISION 或 NULL，单位 μg/m³。

索引：
  ix_measurements_station_id (station_id)
  ix_measurements_observed_at (observed_at)
  ix_measurements_station_observed (station_id, observed_at)

三、上报测量数据
----------------------------------------
POST /api/v1/measurements
Content-Type: application/json

请求字段：
  station_id      必填，字符串，1–64 字符，去空白后不能为空。
  observed_at     可选，带时区的 ISO 8601 时间；省略时使用服务器当前 UTC 时间。
  temperature     必填，-100–100。
  humidity        必填，0–100。
  wind_speed      可选，0–100，或 null。
  wind_direction  可选，0–360，或 null。
  co2             可选，0–100000，或 null。
  pm25            可选，0–10000，或 null。
  pm10            可选，0–10000，或 null。

成功响应：201 Created
  {
    "id": 1,
    "station_id": "station-01",
    "observed_at": "2026-11-04T00:30:00Z",
    "received_at": "2026-11-04T00:30:01Z",
    "temperature": 21.6,
    "humidity": 63,
    "wind_speed": null,
    "wind_direction": null,
    "co2": null,
    "pm25": null,
    "pm10": null
  }

说明：
- 省略可选字段与显式传 null 等价，数据库保存为 NULL。
- 响应中的可选字段始终存在，不会用 0 冒充缺失值。
- 时间统一以 UTC 返回。

四、查询历史数据
----------------------------------------
GET /api/v1/measurements

查询参数：
  station_id  可选，按站点筛选；空白视为不筛选。
  start       可选，带时区 ISO 8601，闭区间起点。
  end         可选，带时区 ISO 8601，闭区间终点。
  offset      可选，默认 0，必须 >= 0。
  limit       可选，默认 100，范围 1–1000。

排序：observed_at DESC, id DESC
成功响应：200，JSON 数组。

错误：
  422 start 晚于 end、时间缺少时区、limit/offset 越界。

五、查询最新数据
----------------------------------------
GET /api/v1/measurements/latest?station_id=station-01

station_id 可选；不传时返回全部站点中最新的一条。
有数据：200，单条测量。
无数据：404，problem+json。

六、健康检查
----------------------------------------
GET /health
数据库可用：200 {"status":"ok"}
数据库不可用：503 problem+json

七、错误响应
----------------------------------------
统一使用 RFC 9457 problem+json：

  {
    "title": "Unprocessable Entity",
    "status": 422,
    "detail": "station_id: must not be blank"
  }

400 Bad Request
  请求体不是合法 JSON，包括 NaN/Infinity 字面量。

415 Unsupported Media Type
  Content-Type 不是 application/json。

422 Unprocessable Entity
  字段缺失、类型错误、数值越界、station_id 空白或过长、时间缺少时区、
  start 晚于 end、limit/offset 越界。

500 Internal Server Error
  数据库或其他服务端异常。

八、环境变量
----------------------------------------
DATABASE_URL
  必填。仅支持 PostgreSQL：
  postgresql://weather:weather@127.0.0.1:5433/weather
  兼容 postgres:// 前缀；拒绝 sqlite:// 和 postgresql+psycopg://。

TEST_DATABASE_URL
  测试用。库名必须以 _test 结尾，否则测试拒绝运行。
  默认：postgresql://weather:weather@127.0.0.1:5433/weather_test

CORS_ORIGINS
  默认：http://localhost:5173,http://127.0.0.1:5173
  多个地址用英文逗号分隔；设为 * 时不启用 credentials。

APP_NAME
  默认：Campus Weather Monitor API

PORT
  默认：8000

DB_PORT
  Compose 数据库映射到宿主机的端口，默认 5433。

WEB_PORT
  Compose Web 映射到宿主机的端口，默认 8080。

九、本地运行
----------------------------------------
前置：Go 1.27+、Node 22+、pnpm 11+、PostgreSQL 17+。
本机当前没有 Go 时：brew install go

  cp .env.example .env
  docker compose -f docker-compose.example.yml up -d db

  set -a
  . ./.env
  set +a

  pnpm install
  make api
  pnpm dev

API 启动时自动执行 goose 迁移。手动命令：

  make migrate
  make migrate-status

十、迁移
----------------------------------------
- 启动时在 PostgreSQL advisory lock 内执行 goose up，多实例不会并发改表。
- 旧版 Python 服务用 create_all 建过表时，先执行：
    make migrate-stamp
  即 goose stamp 1，只写版本号，不重建表。
- 新增迁移：在
    apps/api/internal/platform/migrate/sql/
  下添加带 -- +goose Up / -- +goose Down 的 SQL 文件。
- 不要修改已经应用的迁移。
- goose down 会删表和数据，只允许用于测试库。

十一、数据保留与备份
----------------------------------------
数据永久保留：
- 没有 TTL、定时清理、归档或降采样任务。
- 没有 DELETE 接口。
- measurements 表只增不减。

备份（Compose）：
  docker compose exec -T db pg_dump -U weather -Fc weather > weather.dump
  cat weather.dump | docker compose exec -T db pg_restore -U weather -d weather --clean --if-exists

docker compose down 保留 weather-data 命名卷。
docker compose down -v 会删除全部数据，禁止在真实部署中使用。

十二、容器部署
----------------------------------------
  cp docker-compose.example.yml docker-compose.yml
  docker compose -f docker-compose.yml up --build -d

端口：
  API：8000（设备上报地址保持不变）
  Web：8080（nginx 代理 /api、/health、/openapi.json、/docs）
  PostgreSQL：Docker 命名卷 weather-data 持久化数据，仅绑定宿主机 127.0.0.1:5433
  测试库初始化脚本固化在 docker/db/Dockerfile 构建的镜像中

API 镜像为多阶段构建的 distroless nonroot，迁移 SQL 内嵌在二进制中。

生产环境必须替换示例密码、限制 CORS_ORIGINS，并通过 HTTPS 反向代理暴露服务。

十四、设备接入
----------------------------------------
上报：
  POST http://<server>:8000/api/v1/measurements
  Content-Type: application/json

  {
    "station_id": "station-01",
    "observed_at": "2026-11-04T08:30:00Z",
    "temperature": 21.6,
    "humidity": 63.0
  }

说明：
- station_id 由固件配置，默认 station-01。
- 温度取 Modbus 寄存器 0x0001 的有符号值 ÷ 10。
- 湿度取 Modbus 寄存器 0x0000 的无符号值 ÷ 10。
- 设备默认每 60 秒聚合上报一次。
- 设备通过 SNTP 获取 UTC 时间；未同步时省略 observed_at。
- 风速、风向、CO2、PM2.5、PM10 不在当前设备上，缺失即 null。
- 服务必须监听 0.0.0.0 才能被局域网设备访问。
- 接口没有鉴权，只应部署在受控局域网或带鉴权的反向代理之后。

十五、已移除的旧栈
----------------------------------------
- SQLite、Python、FastAPI、SQLAlchemy、Alembic 已全部移除。
- 旧 SQLite 数据按用户确认不迁移、不导入。
- 旧 PostgreSQL 库可保留数据，通过 goose stamp 接管版本。
